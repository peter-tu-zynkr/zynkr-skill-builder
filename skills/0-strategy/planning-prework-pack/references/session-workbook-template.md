# Session workbook template — tab and column layouts `planning-prework-pack` reproduces

> Skill-specific reference (only this skill ships it). It documents the SHAPE of the
> template workbook (`planning-sources.md` §A — the July 2026 session workbook at the
> time of writing), the designed deck, the per-owner one-pager Doc and the logistics
> packet, so `SKILL.md` can stay short. It never carries cycle content: every
> number, owner and ID comes from the run (tracker · plan Docs · 1:1 Docs · the user) or
> from `./references/planning-sources.md`. Anything you cannot source is written as
> `（待補）` plus the source you would need.
>
> The template Sheet and deck IDs live in `planning-sources.md` §A ("Session workbook",
> "Designed deck"). Copy them; never fill the template originals in place.

## 1 · Workbook — five tabs, in this order

Names are exact (they are what the template workbook carries; a fresh copy already has
them). Row 1 of every tab is a one-line banner in caps; the header row follows. Row
extents below are the template's at the time of writing — `SKILL.md` Step 3 reads the
copy's real row count before clearing, and sizes write ranges to the new cycle's rows.

### 1.1 `Read Me` — key/value rows (col A key · col B value)

Blocks in order (blank row between blocks; block titles are single-cell caps rows):

| Block | Rows |
|---|---|
| Title | `ZYNKR <CYCLE> PLANNING SESSION` · `Looking Back · Looking Forward · Focus the Now` · one-line thesis for the cycle (from the integrated plan Doc addendum, or `（待補）`) |
| Basics | `Session goal` · `Date` (`YYYY-MM-DD` or `TBD`) · `Duration` (`~3 hours · HH:MM–HH:MM · 175 min programmed + ~5 min slack`) · `Attendees` (roles, read from the tracker 負責人 column — never a remembered roster) |
| `PASS / FAIL FOR THIS SESSION` | exactly 3 numbered lines — pack §4 "pass/fail bar" adapted to the cycle (converged Do-now set with owner + next step + start-date · C1 floor pressure-tested · founder-time blocks calendared) |
| `THE 3-PART METHOD` | 3 rows: `Part 1 — Looking backwards…` · `Part 2 — Looking forward…` · `Part 3 — Focus the now…` (pack §5) |
| `EISENHOWER LEGEND  (Urgency × Importance)` | 4 rows: `Do now` · `Schedule` · `Delegate` · `Drop / Defer` — the seed vocabulary of the workbook; the tracker later maps them to P0–P3 (pack §3) |
| `PRE-WORK  (every owner completes before the session)` | numbered rows: `1` the one-page slide instruction (Top-3 delivered w/ proof number · Top-3 goals w/ target number · raw laundry list) · `2` the self-rating rule (Importance 1–5 · Urgency 1–5 · quarter tag · "do NOT pre-place on the matrix") · then ONE row per owner: what that person must bring (derived from their LOB's plan Doc + open tracker items — cite where it came from) · last row: the founder's pre-read list |
| `BINDING CONSTRAINTS  (non-negotiable decision inputs)` | `C1 — Cash / runway` · `C2 — Founder SPOF` · `C3 — Product gap` · `C4 — No instrumentation` (pack §4 fill-in; numbers from accounting/runway input or `（待補：需要 <source>）`) · `Roster reality` (who left / joined, uncovered L1s — from the tracker + user) · `Sequencing rule` (pack §4) |
| `TABS IN THIS WORKBOOK` | 4 rows: `Agenda` · `Pre-work by LOB` · `Laundry List + Eisenhower` · `Eisenhower Matrix` with one-line purpose each |
| `LINKS` | `Context folder` (hub folder URL) · `Main Tracker` · `Integrated plan` · `Deck` (once created) — URLs built from IDs in `planning-sources.md` §A |

### 1.2 `Agenda` — the 8-block run-of-show

Row 1 banner `ZYNKR <CYCLE> PLANNING SESSION — RUN OF SHOW`, row 2 sub-banner (`3-hour
block · HH:MM–HH:MM · 175 min programmed + ~5 min slack · Facilitator: <role>`), row 3
header:

`# · Time · Min · Segment · Maps to · Purpose · How to run (facilitation) · Output · Lead`

Eight body rows + one TOTAL row. Timeboxes are the template workbook's design (pack §5);
shift the clock if the user gives a different start time (skill default `09:00`), keep
the minutes:

| # | Min | Segment | Maps to |
|---|---|---|---|
| 1 | 15 | Open — check-in, goal, success criteria, ground rules | Open |
| 2 | 25 | Part 1 — Looking backwards: what we delivered (round-robin) | Part 1 |
| 3 | 30 | Part 2 — Looking forward: vision, the numbers, the sequencing rule | Part 2 |
| 4 | 10 | Break + matrix staging | Break |
| 5 | 30 | Part 3a — Focus the now: laundry-list generation (silent write + round-robin) | Part 3 |
| 6 | 40 | Part 3b — Eisenhower → founder-time gate → owner/commit → dependency pass | Part 3 |
| 7 | 10 | Cash pre-mortem — does the first half as committed breach the floor? | Part 3 |
| 8 | 15 | Close — RACI fill-in, decision log, next steps | Close |
| — | 175 | TOTAL — 175 min programmed within a 180-min block · ~5 min slack | |

`Purpose` = why the block exists (2–3 sentences). `How to run (facilitation)` = the
runbook text: what the facilitator says/does, the timebox inside the block, who speaks
in what order (pack §5 "what the room actually did" — person-by-person round-robin in
Part 1, function-column brainstorm in Part 2/3a). `Output` = the artefact on the wall
when the block ends. `Lead` = role names (facilitator · each LOB owner · Ops for
logistics/RACI). Facts quoted inside blocks (targets, C1 numbers, uncovered L1s) come
from the cycle's evidence — mark `（待補）` when missing. In the Step 2 chat plan the
facilitation cells may appear abbreviated (first line + `…`, "full text at write time");
the Sheet always receives the full runbook text.

### 1.3 `Pre-work by LOB` — one row per L1

Row 1 banner (`PRE-WORK BY LOB — the source for each owner's one-page function slide…`),
row 2 header:

`LOB · Owner · Mandate · Looking back — what we delivered (<prev cycle>) · Looking forward — where we want to be (<cycle>) · KPIs / targets (<cycle> exit) · Top risk`

Exactly 8 body rows, `1.0` … `8.0`, names from pack §2 (L1 numbers never change).
Column sources:

| Column | Source (mark it in the plan) |
|---|---|
| Owner | tracker 負責人 column for that L1's items (+ helpers); an L1 with no owner is written `（待補：no owner in tracker）` — never invented. `All` is not an owner: write the L1's named owners, then 「掛 All：n 項待認領」 (n = that L1's rows with 負責人 = `All`). A name flagged as departed (Read Me `Roster reality` / the user) is listed only after the SKILL.md Step 0.3 confirm |
| Mandate | the LOB plan Doc's opening mandate paragraph (or its newest addendum) |
| Looking back — delivered | bullets `• …`: tracker rows with 狀態 = `完成` for that L1 (quote `#` verbatim + the L1 from 主類別, e.g. `tracker #5.02 (L1 6.0)` — the `#` prefix is positional), plus 1:1 Doc WB entries in the window (quote the WB date), plus pasted CHANGELOG-style lists if the user gave them; each bullet carries its proof number or `（待補）`. `YE` header reads `Looking back — what we delivered (H1 + H2)`; when the tracker has 0 `完成` rows, fill from the fallbacks in SKILL.md Step 1.1 (`H1 回顧總結` · 年度計畫 digests · CHANGELOG lists · pasted) before writing `（待補）` |
| Looking forward | bullets from the plan Doc's forward section / addendum + tracker `進行中` items |
| KPIs / targets | numbers from the OKR & KPI Tracker `OKRs`/`KPI Dashboard` tabs or the plan Doc; every target quotes a number, or an OKR status-word target (`target: live (OKR row N)` when the row's target is a word and Actual is blank), or `（待補）` |
| Top risk | the plan Doc's risk line; if absent, the C1–C4 constraint that bites this LOB hardest, labelled as the skill's suggestion |

### 1.4 `Laundry List + Eisenhower` — the candidate table

Row 1 banner (`LAUNDRY LIST + EISENHOWER — every candidate initiative across all 8
functions. Impact/Effort/Urgency/Importance + Eisenhower are SEEDS … not verdicts.`),
row 2 header:

`# · LOB · Initiative · Qtr · Impact · Effort · Urgency · Importance · Eisenhower (seed) · Owner · Live decision →`

- One row per candidate, grouped by L1 (`1.0 Marketing` … `8.0 Finance`), `#` running.
- Sources: plan Doc forward bullets + tracker rows with 狀態 ∈ {`未開始`, `進行中`}
  (quote tracker `#` in a trailing note if useful) + the user's additions.
- `Qtr` vocabulary per cycle — `H1`: {`Q1` · `Q2` · `ongoing`} · `H2`: {`Q3` · `Q4` ·
  `ongoing`} · `YE` (plans the NEXT year): {`<year+1> Q1` · `<year+1> Q2` · `<year+1> H2` ·
  `ongoing`}, e.g. `2027 Q1` · `2027 Q2` · `2027 H2`. `Impact`/`Effort` ∈
  {High, Med, Low}. `Urgency`/`Importance` ∈ {High, Med, Low} using the pack §3
  definitions (重要 = moves a top-3 target; 緊急 = gates or expires). U/I values lifted
  from the tracker's own 重要 × 緊急 columns are LAST cycle's call — append
  「(<prev cycle> verdict)」 (e.g. 「(H2 verdict)」) to the Initiative text so the room
  re-rates rather than inherits.
- `Eisenhower (seed)` ∈ {`Do now`, `Schedule`, `Delegate`, `Drop`} — derived from
  U × I; the template workbook's conditional colours key on these exact strings in col I
  (`Do now` #FCE4D6 · `Schedule` #E2EFDA · `Delegate` #FFF2CC · `Drop` #EDEDED) — a
  fresh copy keeps the rules, so use the strings verbatim.
- **Seed-colour range is bound to `Laundry List + Eisenhower!I3:I86`** (84 body rows) in
  the template. If a cycle's laundry list has more than 84 rows, rows beyond 86 render
  uncoloured: either extend each rule's range on the COPY (`manage_conditional_formatting`
  on the new workbook ID, never on the template) to `I3:I<n+2>`, or note the uncoloured
  rows in the Step 7 report. Read the copy's rules first — the bound may have moved.
- `Owner` = tracker 負責人 or `（待補）`. `Live decision →` stays EMPTY — the room fills it.
- Seed sanity (pack §3 lint, warn only): count `Do now`; if > 6 or > 25 % of rows, say
  so in the plan and demote the weakest to `Schedule` only if the user agrees. On a
  `YE` seed this lint is EXPECTED to fire (a full year of carried-in P0s) — print the
  count as a note for the room, never demote silently.

### 1.5 `Eisenhower Matrix` — the 2×2 seed board

Free-form grid, not a table:

- Row 1 banner (`EISENHOWER MATRIX — cross-LOB seed (CANDIDATES, not verdicts)…`).
- Row 3: `''` · `URGENT` · `NOT URGENT`. Row 4: `IMPORTANT` · **DO NOW** cell · **SCHEDULE**
  cell. Row 5: `NOT IMPORTANT` · **DELEGATE** cell · **DROP / DEFER** cell. Each cell is
  a multi-line string: a caps title line, then one bullet per candidate with its LOB
  tag in brackets (`⭐` for Do-now lines, `•` otherwise). Cells are re-derived from
  §1.4 — never typed independently.
- Row 7: the founder-time budget line (`~<h>h/wk × ~<n> weeks = a fixed pool; first
  withdrawal = …; stop adding to Do-now when the pool empties`) — hours from the user
  or `（待補）`.
- Row 8: the `'NOT in <cycle>' PARKING LOT` line (owner: founder; reopen only at the
  mid-cycle gate) listing the Drop items.

## 2 · Deck — 16 slides (template-fill onto the designed deck)

Slide order and the text blocks each one carries. Hand these to `/zynkr-slide` as the
`欄位對映 (field-map)` of a template-fill request (template = the designed deck ID from
`planning-sources.md` §A); if `zynkr-slide` is not installed, print the same 16 blocks
in the chat.

| # | Slide | Text blocks to replace |
|---|---|---|
| 1 | Cover | eyebrow `ZYNKR · STRATEGY OFFSITE` · title `<CYCLE> Planning Session` · subtitle `Looking Back · Looking Forward · Focus the Now` · meta line (date · duration · facilitator role) · one-line thesis |
| 2 | Agenda — Run of Show | 8 rows: start time · segment name · minutes (from §1.2) |
| 3 | How this session works | 3 method cards (Part 1/2/3, one line each) + the 3 pass/fail lines |
| 4 | Part 1 · Looking Back | 5 big-number tiles (value + caption; from the evidence pack / tracker / pasted numbers — `（待補）` tiles are allowed and say so) + `Beyond the numbers` 6 bullets (tracker 完成 highlights across LOBs) |
| 5 | Part 2 · Looking Forward | 6 target tiles (value + caption; from OKR tracker / plan Docs) + one gating sentence (sequencing rule) |
| 6 | Part 3 · the themes | 3–5 numbered theme cards (title + one line, each naming the C1–C4 it relieves) + the converge strip `Silent write → Round-robin → Eisenhower → founder-time gate → Owner + date → Cash pre-mortem` |
| 7–14 | LOB one-pagers `1.0` … `8.0` | L1 number + name · `Owner: <role/name from tracker>` · `LOOKING BACK — DELIVERED` 3 bullets · `LOOKING FORWARD — <cycle>` 3 bullets · `FOCUS NOW — CANDIDATE INITIATIVES` 6 short items · the fixed strip `Do now · Schedule · Delegate · Drop` · footer `Full candidate list (Impact / Effort / U / I) lives in the Sheet.` — all pulled from §1.3 / §1.4 |
| 15 | Eisenhower seed | four quadrant lists (Do-now ★ lines · Schedule bullets `(+N more)` · Delegate · Drop/Defer) + the founder-time gate sentence — from §1.5 |
| 16 | Close | 3 pass/fail lines · founder-time gate line · `NEXT STEPS` 4 bullets (RACI · re-home uncovered L1s · log gates with dates · cadence + mid-cycle reconvene) · closing line `Each person names their #1 commitment before leaving the room.` |

Fixed per-slide footer `Zynkr · <CYCLE> Planning Session` + page number is template
chrome — leave it to the template-fill (recolor = `keep`, the deck is already brand).

## 3 · Per-owner one-pager Doc — 「Pre-work — <cycle>」

One Doc in the hub folder, one H2 per owner (order = tracker 負責人 order), each with
exactly three sections so it maps 1:1 onto that owner's LOB slide:

```
## <owner name from tracker> — <L1 they own>

### 1 · Top 3 delivered（<prev cycle>）
- <item> — proof: <number + source: tracker #N.NN 完成 / WB YYYY/M/D / pasted> ｜ （待補）
- …
### 2 · Top 3 goals（<cycle>）
- <goal> — target: <number + source: OKR row N / plan Doc §> ｜ <status word> (OKR row N) ｜ （待補）
- …
### 3 · Laundry list（self-rate U 1–5 · I 1–5 · quarter）
| # | Initiative | U | I | Qtr | Note |
| 1 | <from §1.4 rows owned by this person> | _ | _ | _ | |
```

Header of the Doc: cycle · session date · due date for pre-work (this skill's default:
5 WORKING days before the session, counting back over Mon–Fri only — a Saturday or
Sunday session ⇒ the preceding Monday — unless the user set one) · the two self-rating
definitions (pack §3) · "do NOT
pre-place on the matrix — we do that live". Names in the Doc are read from the tracker
at run time; example payloads in this file use `王小明` / `Jane` only.

## 4 · Logistics checklist + invite text (sources §C conventions)

Checklist (print; tick what the user confirms; nothing here is executed by the skill
except the optional calendar event on explicit yes):

- [ ] Calendar hold ~8 weeks out — one all-day event `[Place Holder] Zynkr <CYCLE> Planning & Team Building` (create only on explicit yes; `claude_ai_Google_Calendar` `create_event`)
- [ ] Venue booked (Ops) — room name / address / booking confirmation forwarded
- [ ] Lunch + team-building block decided (Ops)
- [ ] Meet link on the event; recording lands as a `Meeting records:` notice
- [ ] Invite updated with the day agenda ~2.5 weeks out (planning block · lunch · team-building)
- [ ] Pre-work Doc + workbook links sent to owners with the due date
- [ ] Whiteboard supplies: 6–8 columns pre-drawn (one per L1 for to-be; one per person for as-is), 3 pen colours, stickies; the empty 2×2 + founder-time board for the break
- [ ] Ops pre-writes the RACI template + decision-log skeleton (Close block)
